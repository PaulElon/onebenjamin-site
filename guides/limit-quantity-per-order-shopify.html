How to limit quantity per order in Shopify (including express checkout)

You are launching a limited drop and want "max 2 per order", or you sell wholesale-style packs and need "minimum 6". The usual first try is a theme setting or a bit of code on the product page. That changes what the quantity box allows, but the order is decided later, in the cart and at checkout. This guide covers what Shopify offers natively, why theme-only limits leak, and what actually holds at checkout.

Short answer

  • B2B buyers: Shopify has native quantity rules (minimum, maximum, increment) set per variant in a B2B catalog. They apply to the B2B buyers that catalog is assigned to, not to your regular shoppers.
  • Regular shoppers: Shopify has a built-in add-to-cart limit, but it is one number for the whole store and counts each variant separately. There is no per-product limit, minimum, or total across variants in the standard settings. The way to enforce one is a cart and checkout validation function, which apps use to block checkout until the cart meets your rule.
  • Theme code alone (a max on the quantity input, a script on the cart page) is a display hint. It is not enforcement.

Option 1: Shopify's add-to-cart limit (native, store-wide)

Under Settings > Checkout > Advanced preferences > Add-to-cart limit, Shopify caps how many of each item a shopper can add to one order. Shopify says the setting "is active by default"; stores with fewer than 250 sales start with a recommended limit of 50 (Shopify Help). Its stated purpose is to protect your inventory information and help prevent overselling, not to run a drop. Catches:

  • One number for the whole store. You cannot set 2 for a drop product and 20 for everything else.
  • Per variant. "The maximum quantity applies to each product's variants independently, not to the product or cart as a whole." Shopify's example: with a limit of 30, a shopper can buy 30 red, 30 blue and 30 green t-shirts in one order.
  • No minimums and no custom message.
  • Exceptions. It does not apply to POS carts, draft orders, B2B catalogs with their own quantity rules, logged-in B2B customers, items with inventory tracking off, or items set to continue selling when out of stock.

If one store-wide cap per variant is all you need, use it: it is free and already on. If you need a different limit per product, a total across sizes and colors, or a minimum, read on.

Option 2: B2B quantity rules (native)

In a B2B catalog you can set, per variant:

RuleShopify's definition
Minimum"the fewest number of an item that can be purchased at one time"
Maximum"the greatest number of a product that can be purchased at one time"
Incrementa positive whole number of 1 or more; the default is 1

Catches: the rules are per variant, so a buyer cannot combine variants to meet them (Shopify's example: 5 gray hats and 5 blue hats do not meet an increment of 10). They live in catalogs, which only apply to B2B customers. If your problem is resellers or shoppers on your normal storefront, this option does not reach them. Check your plan in the admin for B2B access.

Option 3: theme or cart-page code (not enforcement)

Setting a maximum on the product page quantity selector is useful as a hint, but it only controls that one input. Shoppers can reach checkout without it: adding the item again from another page, editing quantity in the cart, using a cart permalink, or tapping an express checkout button. Merchants who rely on this report that limits get bypassed, and the same complaint shows up in reviews of limit apps that work at the theme level.

Option 4: checkout validation (what holds)

Shopify Functions include a Cart and Checkout Validation API. A validation function reads the cart and returns an error when a rule is broken. According to Shopify's developer docs:

  • "Validation errors that your function returns always block checkout."
  • It runs for online store carts, custom storefront carts, and "throughout the checkout process", and for accelerated checkouts: "This includes express checkouts, such as Shop Pay, PayPal, Google Pay, and Apple Pay."
  • It also runs on draft orders.
  • If the function itself fails, checkout continues without the check by default. An app can set blockOnFailure so a failed run blocks instead. Ask any limit app which one it uses.
  • A store can have up to 25 active validation functions.

The shopper sees your message on the cart page (in themes that use the cart template) and in checkout, and cannot pay until the cart is fixed.

Minimum order amount (cart total)

"Minimum order $50" is a money rule, not a quantity rule. The B2B quantity rules above count items, so they do not cover it. A checkout validation function can: it reads the cart's subtotal and blocks checkout below your amount. Two details decide whether it behaves the way you expect:

  • What "subtotal" means. Shopify's validation API defines the cart subtotal as "the amount, before taxes and cart-level discounts, for the customer to pay." So with a $50 minimum, a $55 cart passes even if a 20%-off-the-order code brings what the shopper pays below $50. If your minimum must hold after an order discount, set the amount with that in mind.
  • Currency. If you sell in several currencies, a $50 rule means nothing to a cart priced in euros. Check what your tool does then. OneBen Order Limits only compares amounts in the same currency; when the cart's currency differs from the rule's, it blocks checkout rather than guess a conversion.

The same leak as quantity limits applies here: a "minimum order" message in the theme or on the cart page does not stop an express checkout button. The check has to run at checkout.

What a per-order limit does not do

  • It does not stop repeat orders. "Max 2 per order" lets the same person place a second order. Lifetime or per-customer limits need past order history, which a checkout function does not have; they are usually handled by order review or cancellation after the fact.
  • Per product vs per variant. Decide whether "max 2" means 2 of each size or 2 across all sizes, and check that the tool you use counts the way you mean. A limit that counts each variant separately can be beaten by mixing sizes or colors: merchants report exactly that ("You are still able to add this item more than the limitation ... because it has multiple variants", Shopify Community).

Test before launch day

On a development store, or with a hidden test product:

  1. Add one more than your limit and try to check out. You should see your message and be unable to pay.
  2. Try again through a cart permalink and an express checkout button (Shop Pay, Apple Pay). Those skip your theme, so they are where theme-only limits leak.
  3. Mix variants: if "max 2" means 2 across all sizes, put 1 small and 2 large in the cart and confirm it is blocked.
  4. For a minimum order amount, apply an order discount that takes the total below your minimum and check the result matches the rule you wrote down.
